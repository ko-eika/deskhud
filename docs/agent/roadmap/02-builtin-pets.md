# 内置宠物重塑计划

状态：P0–P1 已完成，P2 动画实现与 P3 运行验证进行中，P4 视觉打磨待运行截图确认

## 目标

基于 DeskHud 吉祥物 `assets/icon.svg`，确定并实现两个内置宠物，使它们成为同一角色家族中的雄性和雌性两个个体：

- 两个宠物共享吉祥物的基础轮廓、色彩和视觉语言；
- 不再使用“长者眼睛的球”作为主要外观；
- 两个宠物统一运行窗口尺寸为 `192×192`；
- 贴边时只改变宠物在窗口内的姿态和动画，不改变窗口位置；
- 悬浮、拖拽、点击、贴边和空闲状态具有可辨识的行为动画；
- 保留现有 `PetScene`、输入事件和宿主窗口边界。

本计划独立于 [`01-pet-engine-core.md`](01-pet-engine-core.md)，不修改阶段 A～G 的完成状态，也不将宠物视觉需求写入引擎通用契约。

## 角色与标识

当前角色与迁移关系如下。糯米团和芝麻豆都是新增的内置宠物；旧 `specs` 已迁移为独立的 external WASM 宠物小团子，不属于本计划的两个内置宠物视觉重塑范围。旧 `blob` 包直接删除，不迁移到芝麻豆：

| 来源 / 当前包                                        | 名称 | 性别与性格                | 稳定 ID | 类型 |
|-------------------------------------------------|---|----------------------|---|---|
| 新增 `pet-deskhud-mochi`                          | 糯米团（Mochi） | 雄性；沉稳、可靠、勇敢，带有顽皮和保护欲 | `pet.deskhud.mochi` | 内置 |
| 新增 `pet-deskhud-sesame`                         | 芝麻豆（Sesame） | 雌性；温柔、细腻、聪慧，带有灵巧和好奇心 | `pet.deskhud.sesame` | 内置 |
| 迁移 `pet.deskhud.specs` → `pet-deskhud-dumpling` | 小团子（Dumpling） | 重塑形象，保留宠物行为          | `pet.deskhud.dumpling` | external WASM |

性别不通过单一的粉蓝配色或夸张装饰表达，主要通过眼型、表情、动作节奏、姿态和角色行为区分。糯米团偏沉稳直接，芝麻豆偏柔和灵巧；两者都保留独立性和可爱的个性。名称、性别和角色描述均须进入中英文 i18n，不在 UI 代码中硬编码。

### ID 迁移

ID 是稳定标识，因此改名必须迁移旧 prefs：

```text
pet.deskhud.specs → pet.deskhud.dumpling
```

迁移范围包括当前宠物选择、尺寸、位置、层级以及以旧 ID 为前缀的宠物配置键。迁移后不再注册旧 ID，避免旧包和新包发生重复身份；`pet.deskhud.dumpling` 作为新稳定 ID 由 external WASM 包提供。旧 `blob` 不做迁移。

视觉重做本身不改变 `api_version` 或 `engine`；只有 F 阶段确认需要修改公开 Guest ABI 时才调整兼容版本。

## 视觉规范

### 共同部分

- 使用 `icon.svg` 中的蓝色幽灵吉祥物作为母题；
- 保留圆润身体、顶部高光、浅色主体、深蓝五官和适度脸颊色；
- 宠物预览使用透明背景的吉祥物资源，不直接复用带方形背景的应用图标；
- 两个宠物的身体基准、脸部中心和眼睛坐标统一，便于共享动画参数；
- 不把眼睛、身体或性别字段加入 `deskhud-engine`。

### 糯米团

- 轮廓更厚实稳定，动作有重量感；
- 眼神跟随直接，眨眼较克制；
- 拖拽时表现为努力稳住身体、被拉伸后有力回弹；
- 贴边时像主动寻找掩护，先观察外部再稳稳缩入边缘；
- 点击或受到惊动时先警觉后放松，体现可靠但不呆板的性格。

### 芝麻豆

- 轮廓更轻盈圆润，动作更细腻；
- 悬浮时有柔和摇摆、探身和小幅度回旋；
- 拖拽时表现出灵活调整重心和柔软回弹；
- 贴边时先探头观察，再轻快地缩回或换姿势；
- 眼神、脸颊和动作节奏体现温柔、聪慧与好奇，不依赖夸张装饰。

## 鼠标跟随与眼神

两个宠物都保留“鼠标移动时眼睛跟随”的核心交互，但表现方式应符合各自性格：

- 眼睛根据宿主提供的 `pointer_dir` 平滑转向鼠标方向，不直接读取屏幕坐标或窗口句柄；
- 鼠标停止移动一段时间后，眼神缓慢回到自然位置，不突然弹回；
- 鼠标移动幅度较小时只移动瞳孔，幅度较大时可以带动轻微侧头或身体朝向；
- 点击时允许短暂放大眼神反应，但结束后回到正常跟随状态；
- 贴边时仍然跟随鼠标，但眼神和探头方向要服从贴边姿态，避免眼睛朝向与身体动作冲突；
- 拖拽时降低或暂时冻结跟随幅度，避免眼睛抖动，松手后平滑恢复。

糯米团的眼神跟随应更直接、稳定，像是在认真观察鼠标；芝麻豆的眼神跟随可以更灵活，带有轻微提前量或短暂回望，但不能造成晕动感。现有 `follow_eyes` 配置项继续保留并扩展到两个宠物；关闭后眼睛保持自然中心或仅响应点击等局部表情。

## 尺寸与窗口行为

两个 `PetKindInfo` 和对应 `manifest.toml` 都使用：

```text
window_width  = 192
window_height = 192
```

窗口位置、吸附、拖拽和命中边界继续由宿主壳处理。宠物包只能读取 `DockState` 和 `DragState`，不得调整 HWND 或其它平台窗口几何。

“躲到边缘”定义为窗口内部的局部姿态变化：

- 左边：身体向左侧收缩或偏移；
- 右边：身体向右侧收缩或偏移；
- 上边：身体向上压缩或探头；
- 下边：身体向下沉伏或弹动。

姿态必须保留在 `192×192` 场景范围内，避免因节点越界导致视觉裁切或命中区域错位。

## 状态与动画

状态采用“基础状态 + 叠加反应”的方式组合。拖拽期间覆盖普通悬浮反应；贴边姿态和悬浮反应可以同时存在：

```text
拖拽覆盖其它状态
贴边姿态 + 悬停反应
贴边姿态 / 悬停反应 / 空闲姿态
```

| 状态 / 组合 | 糯米团 | 芝麻豆 |
|---|---|---|
| 空闲 | 沉稳呼吸，偶尔警觉地眨眼或环顾 | 轻柔上下浮动，偶尔摇摆、回旋或眨眼 |
| 悬停 | 侧头确认来者，眼神直接聚焦 | 探身靠近，带着好奇观察，脸颊或高光短暂增强 |
| 拖拽 | 努力稳住身体，拉伸后有力回弹 | 灵活调整重心，柔软倾斜并轻快回弹 |
| 左右贴边 | 先观察外侧，再像寻找掩护一样缩入边缘 | 先探头偷窥，再轻巧地缩回或换姿势 |
| 上下贴边 | 压扁、稳稳贴住边缘或短暂探出 | 弹性吸附、轻轻抬头或下沉 |
| 贴边 + 悬停 | 从边缘探出更多身体，眼睛转向指针，随后谨慎缩回 | 从边缘快速探头，眼睛和脸颊产生轻快回应，再留下小幅摇摆 |
| 点击 | 警觉睁大眼，短暂后仰后恢复镇定 | 受惊弹起、快速眨眼，再带着好奇恢复 |

其中“贴边 + 悬停”是独立的组合表现，而不是简单地把普通悬停动画叠加到中央姿态上：动画的位移、变形、眼神和节奏都必须以当前贴边方向为基准。例如左边贴边时向左探出，顶部贴边时向下探头，不能统一向场景中心或固定方向移动。

动画由宠物包自身根据 `time_secs`、`PetEvent`、`DockState`、`DragState` 和 `MouseState` 计算。宿主只校验并渲染 `PetScene`。

## 与 F 阶段的关系

本计划不等待 G 阶段。G 是原生后端评估，继续后置。

在实现宠物之前，F 阶段至少应完成以下契约冻结工作：

- WIT 中的宠物生命周期和事件方向；
- WASM Guest 输出 `PetScene` 的方式；
- Sprite、atlas、基础图形和路径资源的引用语义；
- 节点数量、内存、fuel 和调用耗时限制；
- Rust 内置宠物与 WASM 宠物使用相同的场景语义。

不要求 F 的全部安全加固完成后才制作宠物。可以先完成最小 WASM Guest 闭环，再实现内置宠物，并用新宠物的动画需求验证 F 的资源和节点表达能力。

## 验收标准

- 两个宠物均使用糯米团（Mochi）/ 芝麻豆（Sesame）的新 ID 和名称；
- 两个宠物窗口均为 `192×192`；
- 两个宠物具有一致的吉祥物家族特征，但无需靠颜色即可区分；
- 四边贴边会触发不同姿态动画，窗口位置不因宠物姿态变化而改变；
- 悬停、拖拽、点击、贴边和空闲状态均有稳定且不冲突的表现；
- 鼠标移动时两个宠物的眼睛都会平滑跟随，停止移动后自然回正，并能与贴边、拖拽状态协调；
- 贴边和悬停可以同时生效，四个贴边方向都有方向正确的组合动画；
- 旧 prefs 能迁移到新 ID，不丢失用户配置；
- 所有用户可见文案都有中英文 i18n；
- 宠物包不依赖 egui、窗口句柄或平台类型；
- `cargo fmt --all`、相关 crate 的 `cargo check` 和测试通过；
- 不需要修改 `01-pet-engine-core.md` 的阶段定义或通用引擎契约。

## 非目标

- 不实现 G 阶段原生 Windows/macOS/Linux 渲染后端；
- 不在引擎中加入性别、眼睛或身体等宠物专用字段；
- 不让宠物包改变窗口位置、尺寸或平台窗口层级；
- 不在第一轮引入 2D 骨骼、网格蒙皮、粒子、物理或 3D 模型；
- 不要求两个宠物共享同一套行为代码，只共享视觉规范和场景语义。

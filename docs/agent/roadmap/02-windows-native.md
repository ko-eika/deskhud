## 目标 1：宠物主窗口

### 目标效果

宠物主窗口使用 Windows 原生 GPU 覆盖层，支持透明合成、局部命中、拖拽、置顶和宠物包行为。

### 实现范围

- Win32 窗口与 D3D11/Direct2D/DirectComposition 合成。
- 宠物包绘制和行为通过平台无关契约接入。
- 宿主负责输入、拖拽、贴边、几何和置顶。

### 验收标准

- [x] 宠物窗口透明、窗口命中和输入路由正常；不要求透明部分鼠标击穿。
- [x] 拖拽跨过阈值后才开始，允许越出工作区，松手后正确贴边/修正并保存位置。
- [x] 左键、右键、键盘及拖拽事件按契约传给宠物包；普通单击不会误触发拖拽。
- [x] 置顶切换只跟随 prefs，设置窗口保持普通层级。
- [x] DPI、多显示器和负坐标正常。
- [x] 切换宠物包后外观、行为、尺寸和场景正确更新。
- [x] 退出后窗口、输入钩子和临时资源无残留。

### 验证状态

状态：已完成；目标 1 全部验收通过

- 验证平台：Windows 实机。
- 已验证：窗口透明、局部命中、输入路由、拖拽、贴边、置顶、DPI、多显示器/负坐标、宠物包切换、退出清理全部通过；键鼠事件监听（按键/鼠标/滚轮触发气泡）已在目标 2 气泡窗完成后补验通过。

### 已知问题

## 目标 2：气泡/对话框独立原生窗口

### 目标效果

使用宿主管理的独立透明 dialogue 窗口承载宠物包气泡，不裁剪宠物主窗口、不改变宠物窗口尺寸，并随宠物状态实时显示和隐藏。

### 实现范围

- 独立 dialogue HWND 与 D3D 合成器。
- `PetPaint` 气泡文字、颜色、圆角、尾巴和主题映射。
- 屏幕避让、层级、穿透、刷新和退出清理。

### 验收标准

- [x] 气泡使用独立原生窗口，不依赖宠物主窗口绘制。
- [x] 气泡内容、样式、显示/隐藏随宠物包状态更新。
- [x] 宠物移动、贴边、置顶和切换时气泡位置与层级正确。
- [x] 气泡不接收鼠标，不影响宠物命中和拖拽。
- [x] 屏幕边界避让和退出清理正常；「气泡与阴影」（`graphics.effects`）关闭后气泡连同阴影整体隐藏，开启后立即恢复。
- [x] 多显示器、DPI、屏幕边界避让和退出清理正常。

### 验证状态

状态：已完成；Windows 实机验收通过

- 验证平台：Windows 实机。
- 已验证：气泡由独立 DComp 对话窗承载并可显示；随键鼠事件实时显隐；不接收鼠标（不影响宠物命中/拖拽）；屏幕避让与退出清理正常；「气泡与阴影」开关即时生效。
- 根因确认：气泡显示受“气泡和阴影”（`graphics.effects`）总开关控制，此前特效关闭导致 `dialogue_scene` 恒为 `None`。
- 窗口修正（保留）：对话窗移除 `WS_EX_LAYERED`（与 DirectComposition 绑定冲突），并创建即 `WS_VISIBLE`（与宠物窗一致）。

### 已知问题

- 问题：无确认的运行问题；多显示器/负坐标需硬件（暂缓）。

## 目标 3：右键菜单

### 目标效果

使用 Windows 原生菜单提供设置、置顶、插件开关、HUD 布局和退出等操作，并保持主题、字体、分隔线、勾选和禁用状态一致。

### 实现范围

- Win32 原生菜单和命令桥。
- 根据右击点与宠物位置进行菜单定位。
- 插件关闭时禁用 HUD 布局入口。

### 验收标准

- [ ] Win10/Win11 浅色、深色主题显示正常。
- [ ] 菜单文案完整来自 i18n；切换中文/英文后菜单文案立即正确更新，不得硬编码。
- [ ] 应用字体、字号和主题配置能影响菜单样式；缺失翻译按既定回退规则显示。
- [ ] 横线分割、置顶勾选、插件开关勾选和布局禁用状态正确。
- [ ] 菜单在四角定位和屏幕/DPI 边界下正常。
- [ ] 设置、布局、置顶、插件开关和退出动作正确，菜单与宠物/设置窗口生命周期分离。
- [ ] 菜单失焦、Esc、再次右击、打开设置、返回宠物和重复打开流程稳定。
- [ ] 菜单显示期间宠物保持正确置顶关系，设置窗口不被设为置顶。
- [ ] 菜单退出和应用退出时无残留窗口、输入捕获或崩溃。

### 验证状态

状态：进行中；定位已优化，Win10/Win11 实机验收待补

- 验证平台：macOS 已完成菜单迁移，但不是 Windows 菜单验收环境。
- 已验证：Windows 原生菜单和命令桥代码已接入。
- 已优化：菜单改为以右击点为锚点（贴近宠物常出现处），并用 `SPI_GETWORKAREA` 把锚点限制在主工作区内，避免贴边右击裁出屏幕；命令（设置/置顶/HUD/布局/退出）经命令桥分发，设置保存后经 `request_prefs_reload` 即时生效。（`native_menu.rs`）
- 未验证：菜单样式、四角/DPI 定位、Win10/Win11 系统行为、生命周期与退出清理待实机验收。

### 已知问题

- 问题：**缺陷（Windows 原生菜单不随应用/系统主题）**——经典 `CreatePopupMenu`/`TrackPopupMenuEx` 在 Win10/11 不自动暗色，且 uxtheme `SetPreferredAppMode`/`AllowDarkModeForWindow` + owner `DwmSetWindowAttribute` 三套钩子实机均不生效；曾试制 owner-draw 主题菜单但导致菜单异常，代码已回滚。
- 修复状态：待开发（归入「每平台原生」C 计划，C0 试制已回滚，C1 跨平台原生视图 trait 待做）。
- 验证情况：命令桥接入正常；右击点定位与工作区避让已应用；主题样式跟随为已知缺陷。

### 已知问题

# DeskHud 主动实施计划

本目录保留当前有效的宠物引擎与 HUD 主动计划。旧的原生 UI、平台窗口和已废弃插件包路线不在主动里程碑内；相关提交仍可通过 Git 历史追溯。

## 总原则

1. 第一版运行态使用 `deskhud-egui`，用于验证引擎和包协议。
2. 宠物包决定外观、部件、动画和行为；引擎不内置眼睛、身体等宠物特征。
3. 引擎只输出/消费平台无关数据，不依赖 egui 或平台 API。
4. `deskhud-egui` 只是 `PetScene` 的一个渲染适配器，不得反向定义宠物外观。
5. 内置 Rust 宠物和社区 WASM 宠物必须共享同一套语义。
6. 原生平台后端只有在中性场景协议稳定后才单独评估。
7. HUD 保持每屏一个合成窗、同层绘制；HUD 组只组合中性帧，不为成员创建额外窗口。
8. HUD 定义、用户实例和布局分离，使跨插件分组与同一定义的多实例共享一套模型。

| J 便签插件 | 待实施 | 可创建多个实例并参与 HUD 分组的便签 |

## 阶段验收约定

- 每个阶段都必须保持 workspace 可检查、可测试、可回退。
- 宠物包不得依赖 egui、窗口句柄或平台类型。
- 任何用户可见文案继续经过现有 i18n 机制。
- 仅当包兼容契约或公开 ABI 变化时，才调整 `api_version` / engine 兼容族。

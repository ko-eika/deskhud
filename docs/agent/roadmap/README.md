# DeskHud 宠物引擎计划

本目录只保留当前宠物引擎的主动计划。旧的原生 UI、平台窗口和插件包路线已移出主动里程碑；相关提交仍可通过 Git 历史追溯。

## 总原则

1. 第一版运行态使用 `deskhud-egui`，用于验证引擎和包协议。
2. 宠物包决定外观、部件、动画和行为；引擎不内置眼睛、身体等宠物特征。
3. 引擎只输出/消费平台无关数据，不依赖 egui 或平台 API。
4. `deskhud-egui` 只是 `PetScene` 的一个渲染适配器，不得反向定义宠物外观。
5. 内置 Rust 宠物和社区 WASM 宠物必须共享同一套语义。
6. 原生平台后端只有在中性场景协议稳定后才单独评估。

## 里程碑

| 里程碑 | 状态 | 目标 |
|---|---|---|
| A 契约清理 | 已完成 | 清除 `PetPaint` 中固定宠物特征，确定输入/输出边界 |
| B 中性场景帧 | 已完成 | 建立节点、资源、变换、文本和命中区域协议 |
| C 内置宠物迁移 | 已完成 | 现有宠物完全由包资源和包行为组成 |
| D egui 首版运行链 | 已完成 | 在 `deskhud-egui` 中正常加载、切换、动画和交互 |
| E 包运行时 | 已完成 | 资源校验、配置、错误隔离和包生命周期闭环 |
| F WASM Guest | 已完成 | WIT 定义接口，Wasmtime 加载社区宠物行为 |
| G 原生后端评估 | 后置 | 根据协议能力和实际需求决定是否实现各平台渲染器 |

## 阶段验收约定

- 每个阶段都必须保持 workspace 可检查、可测试、可回退。
- 宠物包不得依赖 egui、窗口句柄或平台类型。
- 任何用户可见文案继续经过现有 i18n 机制。
- 仅当包兼容契约或公开 ABI 变化时，才调整 `api_version` / engine 兼容族。

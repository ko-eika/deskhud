# macOS 独立菜单文字错位与字形渲染异常

- 状态：未解决
- 版本：0.6.4
- 平台：macOS
- 优先级：高

## 现象

在宠物右键菜单中，中文和英文菜单项会出现文字错位、字形拼接或字符位置异常。问题不是单纯的缺字：同一菜单项在鼠标悬浮前后可能改变排列，部分字符像被拆开或发生横向偏移。

## 复现步骤

1. 在 macOS 启动 DeskHud。
2. 右键宠物唤出菜单。
3. 移动鼠标经过不同菜单项，观察中文、英文和分隔线附近的文字。
4. 关闭菜单后再次唤出，必要时打开设置窗口再返回菜单，观察问题是否变化。

## 当前确认

- 菜单仍由 egui 提供，未引入第二套产品 UI。
- macOS 菜单已使用独立原生控制面承载，问题仍可复现。
- 已尝试固定字体配置、移除菜单文本的动态测量/省略逻辑、调整菜单表面清屏方式；均未形成可验收修复。
- 不能将该问题直接归因于字体缺失；需要继续检查 macOS GL surface 的逻辑尺寸、scale factor、egui painter 生命周期、纹理上传以及重绘时序。

## 后续排查方向

- 记录菜单窗口的逻辑尺寸、物理尺寸、scale factor 与 egui `pixels_per_point`，确认创建、调整大小和绘制使用同一组值。
- 检查独立菜单 surface 的 GL context、egui context、纹理和 painter 是否跨窗口复用或在窗口销毁后继续使用。
- 在固定窗口尺寸、固定字体和无 hover 动画的最小场景中复现，区分布局坐标错误与 glyph atlas/纹理上传错误。
- 在确认根因前，不继续通过改文案、截断字符串或单纯调整字体大小掩盖问题。

## 验收标准

- 中文、英文菜单项在首次唤出、重复唤出、hover 切换以及打开/关闭设置窗口后均保持字形完整、基线一致、位置稳定。
- 菜单项状态和 hover 动画持续更新，且不影响宠物窗口动画。
- macOS 日志中不出现与该菜单 surface 相关的 GL 错误或资源生命周期警告。
